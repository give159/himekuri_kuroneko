# 単一HTMLツールを出荷前に手動テストする ― 黒猫先生の日めくり v2.0 PRO 実践編

## はじめに

自動テスト（jsdom）に通っていても、実ブラウザでしか分からない問題があります。音・声・タッチ・保存・通信まわりです。この記事では、単一HTMLツール「黒猫先生の日めくり」を例に、**約20分で回せる手動テストの手順**を、期待結果つきでまとめます。そのまま自作ツールの出荷前チェックにも流用できます。

## 前提

| 項目 | 内容 |
|---|---|
| テスト対象 | 黒猫先生の日めくり_v2_0_PRO.html（単一ファイル） |
| 環境1（必須） | PCブラウザ（ChromeまたはEdge） |
| 環境2（必須） | スマートフォンの縦画面 |
| 環境3（任意） | プライベートブラウズ（仕様確認用） |
| 準備 | ファイルをダブルクリックで開くだけ。サーバ不要 |

テストの原則は3つです。

1. **正常系→異常系の順**でやる（まず動くことを見る）
2. **期待結果を先に読んでから**操作する（見落とし防止）
3. 気づいたことは**その場で1行メモ**（後でまとめて書くと忘れる）

---

## 1. 起動テスト（1分）

**手順**：ファイルをダブルクリックして開く。F12で開発者ツールのConsoleを表示。

**期待結果**
- [ ] 画面が表示され、Consoleに赤いエラーが**0件**
- [ ] 日付・時計が現在時刻で表示され、**1秒ごとに進む**
- [ ] フッターのバージョンが **v2.0 PRO**

> エラーが出た場合：全文をコピーして保存。行番号つきで原因箇所が特定できます。

## 2. 推し台詞・気分チップ（2分）

**手順**：「この時間の、推し台詞」カードの気分ボタン（静寂・甘々・毒舌・遊び心など）を順に押す。

**期待結果**
- [ ] 押すたびに台詞のメタ表示（気分名）が切り替わる
- [ ] どの気分でも台詞が空にならない

## 3. AI相談 ― 3経路すべて（5分）

このツールの心臓部です。**3つの経路を別々に**確認します。

### 3-1. ローカル応答（既定・オフライン）

**手順**：Wi-Fiを切る → 相談欄に「集中できない」と入力して送信。

**期待結果**
- [ ] 通信なしでも黒猫先生が応答する（無応答にならない）

### 3-2. 手動APIキー経路

**手順**：Wi-Fiを戻す → 設定でAPIキーを入力 → 「今日の予定を整理したい」と送信。

**期待結果**
- [ ] 外部AIの応答が返る
- [ ] デバッグ虫のログでキーが ******＋末尾4桁** に伏せ字されている

### 3-3. 失敗時フォールバック

**手順**：わざと**間違ったキー**（例：`sk-test`）を設定して送信。

**期待結果**
- [ ] エラーで止まらず、**ローカル応答に切り替わって**返事が来る
- [ ] 待たされる場合も一定時間で打ち切られる（タイムアウト）

## 4. 音まわり（3分）

自動テストで最も再現しにくい領域です。**実機の耳で**確認します。

**手順**：ページを開き直す →（何もクリックせずに）BGMボタンを探す → **一度画面をクリックしてから**BGM・ベル・効果音を順に鳴らす。

**期待結果**
- [ ] カフェBGMが**聞こえる音量**で流れる（v2.0で音量是正済み）
- [ ] ベル・効果音が鳴る
- [ ] 読み上げ（先生の声）が再生される。推しボイス設定の低さ・速さ・高さを動かすと声が変わる

> 鳴らない場合の切り分け：①タブのミュート → ②端末音量 → ③一度もクリックしていない（自動再生制限）の順に確認。

## 5. 集中タイマー・アラーム（3分）

**手順**：タイマーを1分に設定して開始 → 完了まで待つ。アラームを現在時刻の1分後に設定して待つ。

**期待結果**
- [ ] タイマーの残り時間が正しく減り、終了時に通知（音・表示）
- [ ] アラームが指定時刻に**1回だけ**鳴る（二重発火しない）
- [ ] タブを裏に回して戻っても、時計・残り時間が**実時間とズレていない**

## 6. 保存の永続化（2分）

**手順**：人格パラメータを適当に変更 → 気分を「毒舌」に → **ページを再読み込み**。

**期待結果**
- [ ] 変更したパラメータと気分が**復元されている**
- [ ] （任意）プライベートブラウズで同じ操作 → ウィンドウを閉じて開き直すと**消えている**（これは仕様）

## 7. セキュリティ即席チェック（2分）

**手順**：相談欄に次を貼って送信。

```
<img src=x onerror="alert(1)">
```

**期待結果**
- [ ] アラートが**出ない**（出たらXSS脆弱性。出荷停止）
- [ ] 入力した文字列がそのまま**文字として**表示される

## 8. スマホ実機（3分）

**手順**：ファイルをスマホに送って（またはクラウド経由で）ブラウザで開く。縦画面で全カードをスクロール。

**期待結果**
- [ ] 横スクロールが発生しない（レイアウト崩れなし）
- [ ] ボタンが指で押せる大きさ
- [ ] 肉球ふみふみ・しっぽ撫でがタッチで反応し、なつき度が変化する

## 9. 軽いモンキーテスト（2分）

**手順**：2分間、順序を考えずにボタン連打・タブ切替・空入力送信・長文貼り付けなどを乱暴に行う。

**期待結果**
- [ ] Consoleに新しい赤エラーが出ない
- [ ] 画面が壊れず、操作を続けられる

```
      6.保存[ ] 7.XSS[ ] 8.スマホ[ ] 9.モンキー[ ]
気づき：

```

## まとめ

- 手動テストの価値は「**音・タッチ・実時間・実通信**」の4つに集中しています。ここは自動化が苦手な領域です。
- 全9項目で**約20分**。出荷のたびに回しても負担にならない分量に絞りました。
- 1つでも×が出たら、直してから**1番からやり直す**のが結局いちばん速いです（直した箇所が別の場所を壊すことがあるため）。

面白きこともなき世を面白く。
