## 1. 要件定義プロンプト
```
あなたは、初心者にやさしいWeb開発の先生です。
私は【職業・立場】で、【困っていること】を解決する小さなツールを作りたいです。
プログラミングは初心者です。次を、私に質問しながら一緒に整理してください。
専門用語は避けてください。
- 目的（ひとことで）
- 使う人と、その人の困りごと
- 成功の条件（これができたら成功）
- ほしい機能を3つまで
- 今回はやらないこと
- 使う場所（スマホ/PC）とネットの要否
```

## 2. 詳細設計プロンプト
```
次の要件をもとに、初心者でも作れる「単一HTMLツール」の設計を提案してください。
凝った作りは不要、まず動く最小構成で。
出力は次の順で：
- 画面構成（上から順の箇条書き）
- 操作と結果の表（ボタン→起きること）
- 保持する情報（保存する/しない）
- 処理の流れ（起動→操作→保存）
- 異常時の動き（通信失敗・保存失敗のとき）

【ここに要件定義の内容を貼る】
```

## 3. 実装依頼プロンプト（単一HTML）
```
あなたは初心者にやさしいWeb開発の先生です。
次の条件で「1つのHTMLファイルだけで動くツール」を作ってください。

■ 目的：【要件定義より】
■ 使う人：【要件定義より】
■ 機能（この3つだけでOK）：1.【　】 2.【　】 3.【　】
■ 画面の並び（上から）：【設計より】
■ ボタンと動き：【設計より】
■ 覚えておく情報：【設計より／なければ「保存は不要」】
■ 見た目：色・雰囲気【　】／言葉づかい【ていねい/フレンドリー/短く】

■ 技術の約束（そのままコピー）
・style と script を1つのHTMLにまとめる（外部読み込みなし・オフラインで動く）
・保存は localStorage を使い、壊れていても初期状態で必ず起動する
・画面に出す文字は必ずエスケープして安全にする（XSS対策）
・秘密の鍵（APIキー等）はファイルに書き込まない（設定欄で入力）
・スマホの縦画面でも崩れないようにする
・外部AIに接続する場合は任意とし、失敗したらローカルの応答に自動で切り替える

■ 出力してほしいもの
・完成したHTMLの全文
・使い方の3行説明
・あとで直したくなりそうな箇所のメモ
```

## 4. テスト項目生成プロンプト
```
このツールの手動テスト項目を、次の観点で10項目前後に絞って作ってください。
各項目に「手順」と「期待結果」を付けてください。
観点：起動（エラー0）／主要機能/保存の復元/異常系（失敗しても止まらない）/
安全性（<img onerror>でalertが出ない）/スマホ表示（横スクロールなし）/
（音・声・通信があればその確認）
```

## 5. コードレビュープロンプト
```
このコードを、初心者にも分かる言葉でレビューしてください。忖度せず、しかしやさしく。
観点：可読性／安全性（XSS・秘密情報）/保守性（1機能1ブロック）/エラー処理／命名。
各指摘は「なぜ問題か → どう直すか」をセットで、重要度（高/中/低）付きで。
存在しない関数やAPIをでっち上げないでください。確証がなければ「未確認」と書いてください。

【ここにコードを貼る】
```

## 6. 品質モデル（ISO/IEC 25010）プロンプト
```
このツールの品質を、ISO/IEC 25010:2023 の品質特性を骨格に、MECEに点検してください。
ただし小さな個人ツールなので、関係する特性だけに絞って（過剰にしない）。
各特性について「今の状態」と「改善の一手」を1行ずつ。
```

## 7. 直したいときのプロンプト
```
【変えたい所】を【こうしたい】に変えてください。
既存は壊さず、変更点だけを教えてください。理由も一言添えてください。
```


## 8. 初心者サポートプロンプト
```
私は初心者です。今ここで詰まっています：【状況を一言で】。
専門用語を使わず、次に私がやるべきことを1つだけ教えてください。
```

---

### 使い方のコツ
- 上から順に①→②→③…と進めると、要件→設計→実装→テスト→レビュー→品質がそろう。
- 必要なフェーズだけ使ってもよい（例：既存コードのレビューだけ、など）。
- どのプロンプトでも「嘘をつかない／存在しないものをでっち上げない」を最優先に。

*面白きこともなき世を面白く。*
