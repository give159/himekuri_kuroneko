# うさうさ AIツール開発ワークフロー

このスキルは、書籍『黒猫先生の日めくり ― 単一HTMLで作る「推し活AIツール」入門』の
実戦プロンプトを土台に、**1つのHTMLファイルで動くツールを、AIとの対話だけで完成させる**ための
手順とプロンプト集です。初心者にもやさしく、実務にも耐える品質を目指します。

## 使うタイミング
- 単一HTML・オフラインで動く小さなツール（時計・タイマー・AIチャット・学習ツール・推し活ツール等）を作りたいとき
- 要件定義・詳細設計・実装・テスト・コードレビュー・品質確認のどれかを頼まれたとき
- 非エンジニア／初心者が「作りたいけど何から？」と迷っているとき

## 大原則（毎回守る）
1. **嘘をつかない**：存在しない関数名・API・ライブラリ・論文・URLをでっち上げない。確証がなければ「未確認」と明示する。
2. **壊さず足す**：既存コードは触らず、新機能はカード（1機能＝1ブロック）単位で追加する。
3. **初心者ファースト**：専門用語には必ず一言のやさしい説明を添える。相手が非エンジニアなら特に。
4. **WHY→WHAT→HOW**：何を作るかの前に「なぜ・誰のために」を言葉にする。

## ワークフロー（6フェーズ）

各フェーズで、`references/prompt-library.md` の対応プロンプトを使う。ユーザーの段階に合わせて必要なものだけ使ってよい。

### ① 要件定義（何を・なぜ・誰のために）
- 目的・利用者・困りごと・成功条件・機能3つ・やらないこと・動作環境を言葉にする。
- 迷っている相手には、質問で一緒に引き出す（`prompt-library.md` の「要件定義プロンプト」）。

### ② 詳細設計（どう作るか）
- 画面構成（上から順）／操作と結果の表／保持する状態／処理の流れ／異常時の動き。
- 単一HTMLの制約（下記「技術の約束」）を前提に、最小構成で設計する。

### ③ 実装（AIにHTMLを作らせる）
- `prompt-library.md` の「実装依頼プロンプト」を使い、HTML全文を生成。
- **技術の約束**（必ず満たす）
  - style と script を1つのHTMLにまとめる（外部読み込みなし・オフラインで動く）
  - 保存は localStorage。壊れていても初期値で必ず起動する（try-catch＋既定値マージ）
  - 画面に出す文字は必ずエスケープ（XSS対策）
  - APIキー等の秘密情報はソースに埋め込まない（設定欄で入力）
  - スマホ縦画面で崩れない
  - 外部AI接続は任意。失敗時はローカル応答にフォールバックし、無応答にしない

### ④ テスト（壊れていないか）
- `prompt-library.md` の「テスト項目生成プロンプト」で、正常系・異常系・安全性(XSS)・スマホ表示・保存・（音/声/通信があれば）を10項目前後に絞る。
- 各項目に「手順」と「期待結果」を付ける。NGが1つでもあれば直して①から見直す。

### ⑤ コードレビュー（品質を上げる）
- `prompt-library.md` の「レビュープロンプト」で、可読性・安全性・保守性・エラー処理・命名を確認。
- 指摘は「なぜ問題か→どう直すか」をセットで。忖度せず、しかしやさしく。

### ⑥ 品質・リリース（整える）
- 品質の骨格は ISO/IEC 25010:2023 の品質特性を参考に、必要な観点だけ使う（過剰にしない）。
- 版を上げるときは、版表記（表示・ログ・ファイル名）を一致させ、CHANGELOGに1行残す。

## 技術スタックの既定
- 単一HTMLファイル（.html）1枚。HTML + CSS(`<style>`) + JS(`<script>`) を内包。
- 外部依存なし（CDNも使わない）。画像は data: URL で埋め込み。
- 保存は localStorage のみ。通信は任意（外部AI接続時だけ）。

## 相手が非エンジニア／初心者のとき
- コードを見せる前に「何をするものか」を1〜2行で説明する。
- エラーが出たら「エラー文をそのまま貼って」と伝える（要約させない）。
- 専門用語は「HTML＝ブラウザで開くと画面になるファイル」のように言い換える。
