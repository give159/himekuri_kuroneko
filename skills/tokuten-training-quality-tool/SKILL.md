# 【特典】研修品質の単一HTML教材ツール

研修や学習の現場で「そのまま配って動く」品質の、単一HTML教材ツールを作るためのスキルです。
うさうさ研修工房が法人研修で使っている作り方を、書籍購入者向けに整えました。
外部依存ゼロ・機械採点・テスト付きで、**作り直しや引き継ぎに強い**ツールになります。

## いつ使うか
- 研修・学習・練習・診断のための単一HTMLツールを作りたいとき
- 既存ツールに採点・クイズ・タイマー・AIレビューを足したいとき
- ツールに「壊れていないか」を確かめるテストを入れたいとき

## 中核となる4つの原則

### 1. 単一ファイル・外部依存ゼロ
CDN・Webフォント・外部画像を一切使わない（研修先の回線と端末は選べない）。
CSSもJSも同じHTMLに書く。図はインラインSVGで描く。オフラインで動くこと。

### 2. データとロジックの分離（テストが書ける形にする）
教材（設問・解説・フレーズ）は**データ配列**に、採点は**DOMを触らない純粋関数**に置く。
この分離があるからテストが書ける。データを足してもロジックは触らない。
```
データ層   : QUESTIONS / CASES / PHRASES …（教材そのもの。ロジックを含まない）
ロジック層 : score() / buildQueue() …（純粋関数。同じ入力→同じ出力）
基盤層     : Store など（localStorage等を包み、失敗を戻り値に変える）
画面層     : 各タブの描画（DOM操作はここだけ）
```

### 3. 失敗を握り潰さない
保存・通信・音声などの「失敗しうる処理」は try-catch で囲み、失敗しても初期値で動かす。
エラーは無視せず、画面やログに残す。無応答にしない。

### 4. 版と記録を残す
版表記を3箇所（画面・診断ログ・ファイル名）で一致させ、CHANGELOGに1行残す。

## 作る手順
1. 要件（誰の・何を・どう測る）を決める → `references/method.md`
2. データ層を先に作る（設問・解説を配列で）
3. 採点ロジックを純粋関数で書く（DOMを触らない）
4. 画面層で表示・操作をつなぐ
5. **テストを書く**（下記）→ 全部PASSするまで完成と言わない
6. 版を刻む・CHANGELOGを書く

## テスト（jsdom 回帰テスト）
「データとロジックを分離」したから、採点などの純粋関数は**ブラウザなしでテストできる**。
- 単体：`score()` に既知の入力を渡し、期待得点と一致するか
- 結合：保存→読み込みで状態が復元されるか（localStorage）
- 安全性：画面出力がエスケープされ、`<img onerror>` でスクリプトが動かないか
- 回帰：直したあと、全テストを1番からやり直す
詳しい観点とひな形は `references/testing.md` を参照。

## 参照ファイル

- `references/testing.md` … jsdom回帰テストの観点とひな形
