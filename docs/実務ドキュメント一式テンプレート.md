# 特典付録：実務の一連の流れ ドキュメント一式（穴埋めテンプレート）

仕事で「ツールを作って人に渡す」時、実務では次の順で書類が並びます。この付録は、その**全工程をあなた自身のツールで再現できる穴埋めテンプレート**です。【　】を埋めるだけで、実務と同じ書類がそろいます。

> 本書の巻末「技術文書一式」は、この流れを**教材ツール（黒猫先生の日めくり）で実際に書いた完成見本**です。見本と見比べながら、こちらのテンプレートを埋めてください。

## 実務の流れ（全体図）

```
① 要件定義  →  ② 詳細設計  →  ③ 実装仕様  →  ④ テスト  →  ⑤ 利用手順書  →  ⑥ リリース
   何を・なぜ     どう作るか      AIへの依頼      壊れてないか    渡す人向け      版を上げる
```

- **WHY**：この順に書くと、作る前に迷いが消え、作った後に説明できます。
- **WHAT**：6つの書類。どれもA4一枚で十分です。
- **HOW**：上から順に【　】を埋め、各章末のプロンプトをAIに投げます。

# ③ 実装仕様（AIへの作成依頼文）

```
あなたは初心者にやさしいWeb開発の先生です。次の条件で、1つのHTMLファイルだけで動くツールを作ってください。

■ 目的：【①-1】
■ 利用者：【①-3】
■ 機能：FR-01〜03【①-4】
■ 画面構成：【②-1】
■ 操作と結果：【②-2】
■ 保持する情報：【②-3】（不要なら「保存なし」）
■ 異常時：【②-5】

■ 技術の約束（そのままコピー）
・style と script を1つのHTMLにまとめる（外部読み込みなし・オフラインで動く）
・保存は localStorage。壊れていても初期値で必ず起動する
・画面に出す文字は必ずエスケープする
・秘密の鍵はファイルに書き込まない（設定欄で入力）
・スマホ縦画面で崩れない

■ 出力
・HTML全文　・使い方3行　・あとで直しやすい箇所のメモ
```

```

1. これは何？
　【　　　　　　　】ためのツールです。

2. はじめかた
　① 【ファイル】を開く　② 最初に一度【　　　】する

3. 基本の3ステップ
　STEP1【　　　】→【　　　】
　STEP2【　　　】→【　　　】
　STEP3【　　　】→【　　　】

4. こまった時
　| 症状 | 対処 |
　|---|---|
　| 音が出ない | 画面を一度タップ／端末音量を確認 |
　| 保存が消えた | プライベートモードでは消える仕様 |

　入力内容は【この端末内にのみ保存／保存しません】。
　【　　　　　】の入力はご遠慮ください。

6. 連絡先：【　　　　】　作成：【氏名】／版：【v1.0】／日付：【　　】
```

## この6枚がそろうと何が変わるか

- **社内で通る**：「作ってみました」ではなく「要件から手順書まであります」に変わります。
- **引き継げる**：自分以外の人が、直せる・使える・説明できる状態になります。
- **次が速い**：2本目からは、この6枚をコピーして書き換えるだけで済みます。

**WHY**：書類は作業を増やすためでなく、迷いと手戻りを減らすためにあります。
**WHAT**：要件→設計→実装→テスト→手順書→リリースの6枚。
**HOW**：全部A4一枚で十分。埋まらない欄は「未定」と書いて先へ進みましょう。

*完璧な書類より、埋まった書類。まず1周、走り切ることが実務です。*
*面白きこともなき世を面白く。*
