# フリガナつき プログラミング用語じてん ― Why・What・Howでわかる

プログラミングでつまずく理由のひとつは、「読み方が分からない言葉」です。声に出して読めないと、覚えられず、AIにも聞きにくい。この付録は、よく出る用語に**フリガナ**をふり、**Why（なぜ大事）→What（何もの）→How（どう使う）**の順でやさしく説明します。

- 読み方に迷ったら、まずここで確認してください。
- 用語は、本書のツールで実際に登場する順に近い並びにしています。
- 例え話は「※正確ではないが、イメージ用」として添えています。

---

## HTML（エイチ・ティー・エム・エル）

- **Why**：これが無いと、ブラウザに「画面」を出せません。すべての出発点です。
- **What**：ブラウザで開くと画面になる、文書のファイル。この本では、これ1枚にすべてを詰め込みます。
- **How**：メモ帳に書いて、ファイル名を `〇〇.html` で保存 → ダブルクリックで開くだけ。
- ※イメージ：料理でいう「お皿」。この上に文字も絵もボタンも乗せます。

## CSS（シー・エス・エス）

- **Why**：見た目（色・大きさ・配置）を整えないと、読みにくい画面になります。
- **What**：デザインの担当。文字色や余白、ボタンの形などを指定します。
- **How**：HTMLの中の `<style>` というまとまりに書きます。「この文字は青く」などを指定。
- ※イメージ：料理の「盛りつけ」。味は同じでも、見た目でぐっと良くなります。

## JavaScript（ジャバ・スクリプト）

- **Why**：ボタンを押したら動く、といった「動き」はこれが担当します。
- **What**：ツールに動きをつけるための言葉。計算・保存・音などを命令します。
- **How**：HTMLの中の `<script>` というまとまりに書きます。
- ※イメージ：料理の「火入れ」。材料(HTML)に熱を通して、動く料理にします。

## ブラウザ

- **Why**：作ったツールを動かす場所です。特別なアプリは要りません。
- **What**：ChromeやSafari、Edgeなど、ふだんネットを見る画面のこと。
- **How**：HTMLファイルをダブルクリック、またはブラウザにドラッグすれば開きます。

## localStorage（ローカル・ストレージ）

- **Why**：これが無いと、閉じるたびに入力が消えてしまいます。
- **What**：ブラウザの中にある、小さな保存箱。この端末の中だけにデータを残せます。
- **How**：AIに「保存はlocalStorageで」と頼めば組み込んでくれます。約5MBまで・文字だけ保存。
- ※イメージ：机の引き出し。自分の机(端末)の中にだけ、メモをしまえます。

## JSON（ジェイソン）

- **Why**：いろいろな情報を、まとめて保存・やり取りするのに便利です。
- **What**：データを整理して書くための、決まった形式。名前と値の組で書きます。
- **How**：保存の裏側で使われます。ふだんは意識しなくてOK。AIに任せられます。
- ※イメージ：ラベルつきの仕分けボックス。「名前：たろう」のように整理して入れます。

## API（エー・ピー・アイ）

- **Why**：外のサービス(AIなど)の力を、自分のツールから借りるために必要です。
- **What**：プログラム同士をつなぐ「窓口」。本書ではAIに質問を送る入口として登場。
- **How**：AIサービスからもらう「APIキー」を設定欄に入れると使えます（任意）。
- ※イメージ：受付の窓口。決められた頼み方で渡すと、答えが返ってきます。

## APIキー（エー・ピー・アイ・キー）

- **Why**：外部サービスを使う時の「あなたの合鍵」。無ければ外部AIは使えません。
- **What**：本人だけが持つ、長い文字列のパスワードのようなもの。
- **How**：設定欄に貼るだけ。**人に見せない・ファイルに書き込まない**のが鉄則です。
- ※イメージ：家の合鍵。落とすと悪用されるので、大切に扱います。

## 関数（かんすう / function・ファンクション）

- **Why**：同じ処理を何度も書かずに済み、間違いも減ります。
- **What**：「ひとまとまりの作業」に名前をつけたもの。呼べば実行されます。
- **How**：AIが作ってくれます。「〇〇する関数を作って」と頼めばOK。
- ※イメージ：料理のレシピ。「カレーを作る」と名づければ、毎回同じ手順を呼び出せます。

## 変数（へんすう / variable・バリアブル）

- **Why**：数や文字を一時的に覚えておくために必要です。
- **What**：名前をつけた「入れもの」。中身は入れ替えられます。
- **How**：AIが使ってくれます。「点数を覚えておく変数」などと会話で伝えればOK。
- ※イメージ：ラベルを貼った箱。「点数」という箱に、数を出し入れします。

## エスケープ

- **Why**：これをしないと、入力された文字で画面が壊れたり、悪用されたりします。
- **What**：入力された文字を「安全な見た目」に変えてから表示する仕組み。
- **How**：AIに「画面に出す前にエスケープして」と頼めば入れてくれます。
- ※イメージ：外から来た荷物の「安全確認」。中身をそのまま通さず、確認してから出します。

## フォールバック

- **Why**：本命がうまくいかない時でも、ツールを止めないために必要です。
- **What**：失敗した時に切り替える「代わりの動き」。
- **How**：本書のツールは、外部AIが使えない時、自動で内部の応答に切り替えます。
- ※イメージ：エレベーターが止まった時の「階段」。別の手段で目的地に着けます。

## タイムアウト

- **Why**：返事が来ない時にいつまでも待つと、ツールが固まって見えます。
- **What**：「一定時間で待つのをやめる」しくみ。
- **How**：外部への問い合わせに設定します。AIに「タイムアウトを付けて」と頼めます。
- ※イメージ：電話の「呼び出しをあきらめる時間」。ずっと鳴らし続けません。

## デバッグ

- **Why**：不具合(バグ)を見つけて直すのは、ものづくりの当たり前の一部だからです。
- **What**：「どこがおかしいか」を調べて直す作業。
- **How**：エラー文をそのままAIに貼るのが、いちばん速いデバッグです。
- ※イメージ：虫さがし。バグ(虫)を1匹ずつ見つけて、外に出していきます。

## バージョン（版・ばん）

- **Why**：どれが最新か分かるようにして、混乱や差し戻しを防ぎます。
- **What**：ツールの「第何版か」を表す番号(例：v2.0)。
- **How**：直したら番号を上げ、変更点を1行メモ(CHANGELOG)しておきます。
- ※イメージ：本の「第2版」。改訂するたびに版が上がっていきます。

---

## 用語を「自分のもの」にするコツ

1. **声に出して読む**：読めない言葉は覚えられません。フリガナで一度読んでみる。
2. **例え話で掴む**：正確でなくてOK。「引き出し」「合鍵」などのイメージが記憶を助けます。
3. **AIに聞き返す**：それでも分からなければ「【用語】を小学生にも分かるように」と頼む。

## 分からない言葉に出会ったら（コピペ）
```
「【用語】」の読み方と意味を、非エンジニアにも分かるように、
Why(なぜ大事)→What(何もの)→How(どう使う)の順で、短く教えてください。
たとえ話も1つ付けてください。
```

*読めれば、聞ける。聞ければ、作れる。*
*面白きこともなき世を面白く。*
