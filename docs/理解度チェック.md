## 第1章　単一HTMLという設計思想

1. 単一HTMLは、CSSやJavaScript、画像まで1つのファイルにまとめられる。
2. 外部ファイルを読み込む作りにすると、オフラインでは動かないことがある。
3. 単一HTMLは、渡した相手がすぐ開いて使えるのが利点だ。
4. 画像を埋め込むには、必ず別ファイルにしておく必要がある。
5. 保存したデータが壊れていたら、アプリは起動できなくても仕方ない。

**解答**：1.○／2.○／3.○／4.×（data:URLで内包できる）／5.×（既定値で必ず起動する設計にする）

## 第2章　全体アーキテクチャを読む

1. アプリは「状態→描画→操作」の繰り返しで動いている。
2. 機能をカード単位に分けると、追加や削除がしやすい。
3. 起動時にデータを復元する処理は不要である。
4. 変更のたびに保存しておくと、次に開いた時も続きから使える。
5. タブは、複数の機能を切り替えて見せる仕組みだ。

**解答**：1.○／2.○／3.×（load()で復元する）／4.○／5.○

## 第3章　画面と状態のモデル設計

1. 「今の状態」を1つのまとまり(state)に集約すると、保存も復元も一括でできる。
2. localStorageには、数値や画像をそのままの形で保存できる。
3. 保存前に文字列へ変換し、読み込み時に元へ戻す必要がある。
4. データが欠けていても初期値で補えば、アプリは動き続けられる。
5. 保存に失敗したら、アプリ全体を止めるのが正しい。

**解答**：1.○／2.×（文字列のみ。変換が必要）／3.○／4.○（既定値マージ）／5.×（try-catchで守り動かし続ける）

## 第4章　音を作る：WebAudioでBGM・ベル・効果音

1. 音は、音源ファイルを持たなくてもその場で合成できる。
2. AudioContextは、ユーザー操作の前に作っても必ず音が鳴る。
3. 操作(クリック等)の中でresume()を呼ぶと、音が有効になる。
4. 音量は、いきなり最大にするより丁寧に立ち上げる方が自然に聞こえる。
5. 効果音のたびに音声ファイルをダウンロードしている。

**解答**：1.○／2.×（操作前だとsuspendedで鳴らない）／3.○／4.○／5.×（その場で合成している）

## 第5章　声を出す：Web Speech APIで推しボイス

1. 読み上げは、読ませたい文を渡すだけで始められる。
2. 声・速さ・高さを変えると、キャラクターの声を作れる。
3. どの端末でも、使える声の種類はまったく同じである。
4. 使える声が無い場合に備えて、代わりの動きを用意すると安全だ。
5. 推しボイスの設定は、保存しても次回に反映されない。

**解答**：1.○／2.○／3.×（端末により異なる）／4.○（フォールバック）／5.×（保存され反映される）

## 第6章　集中を支える：タイマーと集中スイッチ

1. setIntervalは「1秒ちょうど」を常に保証してくれる。
2. 正確な時刻表示には、都度いまの時刻を読み直すのが有効だ。
3. 背景タブ(裏に回した状態)では、間隔が延びることがある。
4. 集中スイッチのような"遊び"は、続ける力になる。
5. 経過時間は、数えたカウントより引き算で求める方がズレにくい。

**解答**：1.×（保証しない）／2.○／3.○／4.○／5.○

## 第7章　時刻で呼ぶ：アラームと通知設計

1. アラームは「指定時刻になったか」を見張ることで実現できる。
2. 同じ時刻に何度も鳴らないよう、発火済みの印を使う。
3. 通知は、音だけより音＋声＋表示の方が気づきやすい。
4. 時刻の見張りには、専用の特別な仕組みが必ず必要だ。
5. 一度鳴ったアラームは、印がないと連続で鳴り続けることがある。

**解答**：1.○／2.○／3.○／4.×（1秒ループで監視すれば足りる）／5.○

## 第8章　AIを"任意"で統合する

1. AIは必須で、キーが無いと何も応答できない設計が正しい。
2. キーが無くても、ローカル応答で会話が成り立つようにする。
3. 外部への問い合わせには、時間切れで打ち切る仕組みを設ける。
4. タイムアウトすると、通信そのものも即座に取り消される。
5. APIキーは、配布するファイルに書き込んではいけない。

**解答**：1.×（任意。キー無しでもローカルで動く）／2.○／3.○／4.×（打ち切るだけで通信は裏で続く。中断はAbortControllerが必要）／5.○

## 第9章　学びを組み込む：English Studyと対話

1. 学習機能は「表示＋お手本の読み上げ＋自分で発音」で成り立つ。
2. フレーズは、データに項目を足すだけで増やせる。
3. 学習ツールでは、続ける工夫(進捗保存や推し)は重要でない。
4. お手本の読み上げは、端末の音声機能を使っている。
5. データは、英文・和訳・ひとことメモのまとまりで持つと扱いやすい。

**解答**：1.○／2.○／3.×（継続の工夫こそ本体）／4.○／5.○

## 第10章　配布・運用・改善

1. 配布は「1つのファイルを渡すだけ」で完了する。
2. 版番号は、表示・ログ・ファイル名で食い違っていてもよい。

4. リリース後は「小さく直して版を上げる」を繰り返すのがよい。
5. 版を上げる前に、動作の確認(テスト)をしておくと安心だ。

**解答**：1.○／2.×（一致させるべき）／3.○（mask）／4.○／5.○
